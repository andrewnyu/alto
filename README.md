# ALTO

ALTO is a skyline-view visualization and synthesis platform.

## Monorepo Structure

- `backend/` FastAPI (Python 3.12+) service with async orchestration and Google AI/Maps adapters.
- `frontend/` Next.js App Router experience implementing the Horizon Interface.

## Backend Setup

```bash
cd backend
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .[dev]
cp .env.example .env
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

## Frontend Setup

```bash
cd frontend
npm install
cp .env.example .env.local
npm run dev
```

## Required Environment Variables

### Backend

- `MOCK_MODE` to disable real Google calls for deterministic local testing.
- `GEMINI_API_KEY` for Gemini/Nano Banana model calls.
- `GEMINI_MODEL` default `gemini-3`.
- `NANO_BANANA_MODEL` default `gemini-flash-image-3`.
- `GOOGLE_MAPS_API_KEY` for Static Maps, Places, Geocoding.
- `GOOGLE_MAPS_BROWSER_API_KEY` optional browser-facing Maps key.
- `GOOGLE_MAP_ID` optional photorealistic map style.
- `FAR_STREETVIEW_ENABLED` toggles far-anchor Street View probing (default `true`).
- `FAR_STREETVIEW_PROBE_RADIUS_M` metadata probe radius for far anchors (default `120`).
- `PUBLIC_BASE_URL` optional base URL behind reverse proxy.

### Frontend

- `GOOGLE_MAPS_BROWSER_API_KEY` (falls back to `GOOGLE_MAPS_API_KEY` if unset)
- `PUBLIC_BASE_URL` for API base URL (default `http://127.0.0.1:8000`)

## Core Endpoint

- `POST /api/v1/preview`
- Request:

```json
{
  "address": "181 Fremont St, San Francisco, CA",
  "lat": 37.79061,
  "lng": -122.39695,
  "storey_level": 18,
  "heading": 150,
  "time_of_day": "GoldenHour"
}
```

The backend concurrently fetches Street View, satellite imagery, elevation, and location context, derives LumenEngine lighting physics, and runs parallel AI synthesis for a skyline narrative plus final render.

## Skyline Image Generation Logic

### 1) Request Inputs

`POST /api/v1/preview` accepts:

- `address`
- `lat`
- `lng`
- `storey_level` (`0` to `50`)
- `heading` (`0` to `360`)
- `time_of_day` (`Sunrise`, `Noon`, `GoldenHour`, `Midnight`)

`altitude` is derived from storey if not explicitly provided in backend internals (`storey_level * 3.2m`).

### 2) Visual Inputs (Reference Images)

For each request, the backend gathers these references:

- Near Street View (`street_view`)
- Tilt-up Street View (`street_view_tilt_up`)
- Optional far-offset Street View anchor (`street_view_far_anchor`) for elevated floors
- Satellite static map (`satellite`)
- Base geometry fallback (`base_geometry`)

Reference stack passed to the image model:

- `storey_level > 0`: satellite, tilt-up, near street, optional far-anchor, base geometry
- `storey_level == 0`: near street, tilt-up, satellite, base geometry

### 3) Lighting Inputs (Time of Day)

The `LumenEngine` maps `time_of_day` to deterministic lighting profiles:

- `Sunrise`: `2500K`, low-angle light, morning mist
- `Noon`: `5600K`, neutral overhead sun, short shadows
- `GoldenHour`: `3000K`, intense bloom, amber cast, elongated shadows
- `Midnight`: `5000K`, point-light night scene, high-ISO grain

These values are inserted into the image prompt as a lighting directive.

### 4) Prompt Construction

The image render uses a single "cinematographer" prompt that combines:

- Floor/altitude uplift constraints
- Horizon-forward panoramic composition constraints
- Geometry alignment guidance from reference image ordering
- Location context + nearby landmarks
- Terrain/camera altitude notes
- Lighting instruction for the selected `time_of_day`

Prompt style intent:

- Elevated hyper-realistic balcony-perspective skyline view
- Wide panoramic continuity for horizontal panning
- Realistic urban texture and material detail
- Avoid generic stock-photo skyline composition and unsupported landmarks

### 5) Model Invocation and Fallbacks

- The backend sends `parts = [prompt, image_1, image_2, ...]` to the configured image model (default `gemini-flash-image-3`).
- If the model/key is unavailable or generation fails, it falls back to `base_geometry`.
- A guard marks output as fallback if the generated bytes exactly match one of the reference images (reference-echo detection).
